第 2 章 · 写出最小 Transformer 与解码循环 ​

第 1 章里，我们用一条命令拿到了模型的输出。本章的问题是：从 token IDs 进、到下一个 token 出，中间到底发生了什么？ 把这个盒子打开、亲手写出来，后面每一章的"慢在哪、省什么"才有落点。

我们要写的不是论文里的完整架构，而是一个能对齐、能复跑的最小实现：标准 decoder-only block（RMSNorm、RoPE、SwiGLU、GQA 注意力），外加一个贪心解码循环。全部代码在 CPU 上运行，秒级完成。进阶部分再把这份实现对齐到真实权重（Qwen3-0.6B），逐一补齐真实模型里"教学清单之外"的细节。

本章代码在 pi_infer/model.py（模型）与 pi_infer/generate.py（解码），测试在 pi_infer/tests/，实验在 experiments/exp_ch2_forward_alignment/。

2.1 用张量维度把前向串起来 ​

先约定记号。设 batch B=1、序列长度 T、模型维度 d、query 头数 hq、KV 头数 hkv、每头维度 dh=d/hq、词表 V。下表是我们合成小模型（pi_infer.model.build_tiny_model）的默认值：

符号含义tiny 预设值
V词表大小256
d模型维度64
hq / hkvQ 头 / KV 头4 / 2
dh每头维度16
nlayer层数2
dffFFN 中间维176

一次前向的数据流，每一步右侧是张量形状（pi_infer/model.py 可对照）：

text
token_ids            [B,T]           整数，无梯度
 └─ embedding        [B,T,d]         查表：每行是一个可学习向量
    └─ 每层 block ×n_layer
       ├─ attn_norm  [B,T,d]         RMSNorm（无 bias）
       ├─ q_proj     [B,T,h_q·d_h]   → reshape [B,h_q,T,d_h]
       ├─ k_proj     [B,T,h_kv·d_h]  → [B,h_kv,T,d_h]   ← 注意比 Q 少
       ├─ v_proj     [B,T,h_kv·d_h]  → [B,h_kv,T,d_h]

三个容易走错的形状细节：

  1. K/V 的头数与 Q 不同（GQA）。hkv=2<hq=4，两个相邻的 Q 头共享一个 KV 头——第 4 章算 KV 缓存大小时，这一行就是"为什么缓存能省一半"的来源。
  2. "多头"只是 reshape。[B,T,d] 投影后 view 成 [B,h_q,T,d_h]，张量没变，只是解释变了；o_proj 之前再拼回去。
  3. logits 的每一行独立。[B,T,V] 的第 t 行是"看过前 t+1 个 token 后，对下一个 token 的打分"。因果 mask 保证它看不到未来（见 2.2）。

形状报错的三分钟定位法。自己实现时最常见的失败是 reshape 处的 view 尺寸不匹配。定位顺序：从报错的 shape 反推是哪次投影（[B,T,h·d_h] 中哪个 h）；打印 q.shape / k.shape 进 attention 前的值；对照上表逐行核对。TinyConfig.__post_init__ 在构造期就检查整除关系（dmodhq、hqmodhkv、dh 为偶数），把"跑到一半才炸"变成"构造即报错"——这是教学代码刻意示范的防御式写法。

2.2 缩放点积注意力：先手算一次 ​

注意力的核心公式：

Attention(Q,K,V)=softmax(QK⊤dh)V

为什么除以 dh：点积是 dh 项乘积之和，维度越大数值方差越大；不缩放时 softmax 会过早饱和成 one-hot，梯度消失。为什么减 max：softmax 对所有分数加同一个常数不变，减去行最大值让指数最大为 1，防止上溢——这就是"数值稳定 softmax"。

手算例子（与 pi_infer/tests/test_model.py::test_hand_calculated_two_head_three_token_causal_gqa 同源，可先算再看答案）。

设 dh=2、1 个 KV 头、2 个 Q 头，3 个 token。只看 query head 0：

text
q = [[1, 0], [0, 2], [1, 1]]        # 3 个位置的 query 向量
k = [[1, 0], [0, 1], [1, -1]]       # 3 个位置的 key 向量
v = [[2, 3], [5, 7], [11, 13]]      # 3 个位置的 value 向量
1
2
3

因果性：位置 t 只能看到 key 0..t。逐位置算（dh=2）：

  • 位置 0：分数只有一个 q0⋅k0/2=1/2。softmax 单元素=1。输出 =v0=[2,3]。
  • 位置 1：分数 ={q1⋅k0, q1⋅k1}/2={0,2}/2={0,1.414}。 e0=1, e1.414≈4.113，权重 ≈{0.196,0.804}， 输出 ≈0.196[2,3]+0.804[5,7]≈[4.41,6.22]。
  • 位置 2：分数 ={2,1,0}/2≈{1.414,0.707,0}， e 幂 ≈{4.113,2.028,1}，和 ≈7.141， 权重 ≈{0.576,0.284,0.140}， 输出 ≈0.576[2,3]+0.284[5,7]+0.140[11,13]≈[3.96,5.10]。

跑测试验证：

bash
python -m pytest pi_infer/tests/test_model.py -k hand_calculated -q
1

这个例子里还埋了 GQA：query head 1 用的是同一组 k、v。测试断言两个 head 输出不同——它们共享 KV，但各自的 q 不同，所以注意力权重不同。这就是"共享 KV、独立提问"。

因果 mask 的实现（model.py::causal_attention）值得读一次：mask 不是乘 0，而是把"未来位置"填 −∞ 再 softmax——指数直接归零，数学上等价于"根本不存在"。增量解码时（只喂 1 个新 token）查询位置是 start_pos，键位置从 key_start_pos 起，用绝对位置比较而不是"序列内下标"——这保证了第 2 章的增量前向与全量前向在数值上可逐位对齐（实验 3 的前提）。

2.3 RMSNorm、RoPE、SwiGLU：各一个最小例子 ​

RMSNorm（pi_infer/model.py::RMSNorm）。比 LayerNorm 少了均值中心化，只按均方根缩放：

RMSNorm(x)=x1d∑ixi2+ϵ⊙g

手算：x=[3,4]，(9+16)/2+10−6≈3.536，输出 ≈[0.849,1.131]，再逐元素乘可学习的 g。没有 bias，参数只有 g。低精度下的细节：实现里先把输入升到 float32 算平方和再降回原精度——第 5 章量化时这个"精度敏感点"会再现（RMSNorm 的分母是大量平方和，低精度累加误差被开方放大）。

RoPE（旋转位置编码）。把每个 head 的向量两两一组（(x0,x1),(x2,x3),…），第 i 组在第 t 个绝对位置旋转角度 tθi，θi=θ−(2i/dh)：

(x2i′x2i+1′)=(cos⁡tθi−sin⁡tθisin⁡tθicos⁡tθi)(x2ix2i+1)

两个性质，测试都验证了（test_rope_rotation_depends_only_on_absolute_position）：

  1. 只依赖绝对位置：同一个 token 在第 5 位单独旋转，与放在长序列里取第 5 位的结果完全相同——这是"KV 缓存里存已旋转的 K"合法的前提。
  2. 相对性：qt⋅ks 只依赖 t−s（旋转不改变内积的相对结构），模型由此获得"相差几个 token"的概念，而不是记住绝对编号。

SwiGLU（pi_infer/model.py::SwiGLU）：

FFN(x)=Wdown(SiLU(Wgatex)⊙Wupx),SiLU(z)=z⋅σ(z)

门控分支决定"放行多少"，上投影分支决定"放行什么"。三个矩阵都是 d×dff，所以 SwiGLU 的参数量是 3ddff，比普通两层 FFN（2ddff）多一半——这是激活函数换来的表达力成本。

残差与 pre-norm。每个 block 是两次"norm → 子层 → 加回"：

python
x = x + attention(attn_norm(x), ...)     # pi_infer/model.py DecoderBlock
x = x + ffn(ffn_norm(x))
1
2

先归一化再进子层（pre-norm），残差路径上没有归一化——梯度可以无阻地直通第一层。观察维度：残差流里 x 的尺度逐层增长，norm 只在"进子层前"把它压回稳定范围。

2.4 拼出前向与最小生成循环 ​

TinyTransformer.forward（pi_infer/model.py）把上面的部件串起来，同时支持两种调用：

  • kv_cache=None：全量重算。输入整段 token，输出每个位置的 logits——训练时一个 batch 的并行输入就是这个形态。
  • 带 kv_cache：增量。历史 token 的 K/V 已在缓存里，本次只算新 token，位置从 start_pos 偏移。第 4 章会把缓存做成块管理，本章先用最朴素的"整段拼接"版本（SimpleKVCache）。

训练并行 vs 推理逐步——同一前向的两种用法。训练时 T 个位置一次算完、T 个 loss 同时反传；生成时每步只关心最后一行 logits，选出下一个 token 拼回输入。贪心解码循环（pi_infer/generate.py::greedy_decode）：

python
for step in range(max_new_tokens):
    if cache is None:
        input_ids, start_pos = token_ids, 0        # 重算整段
    else:
        input_ids, start_pos = token_ids[-1:], len(token_ids) - 1  # 只喂新 token
    logits = model(inputs, start_pos=start_pos, kv_cache=cache)[0, -1]
    next_id = int(logits.argmax())                  # 贪心 = 每步取 argmax
    token_ids.append(next_id)
    if next_id == eos_id:                           # 停止条件
        break

注意两个边界：最后一行 [0, -1] 是"看过全部已知 token 后对下一个位置的预测"；eos_id 只检查新生成的 token，prompt 里出现 eos 不终止（test_eos_in_prompt_does_not_stop_generation）——与第 1 章服务端停止条件同一条约定。

贪心之外还有采样（第 1 章 1.2 已区分）——按 logits 的 softmax 分布随机抽取。贪心是采样的特例（温度→0），第 7 章验证投机解码时会同时用到这两种口径。

GenerateResult 还带 kv_stats（读写槽位计数）：greedy_decode 用 _CountingCache 包装任意缓存实现统计而不侵入存储——"测量不改变被测对象"的小设计，第 3 章的测量纪律同一思想。

2.5 进阶：真实权重对齐与差异清单 ​

教学实现与真实模型之间隔着若干"教学清单之外的细节"。用 run_qwen3_alignment.py 把 Qwen3-0.6B 的权重装进最小实现、与 transformers 官方前向对照单步 logits。对齐过程中逐一补齐的差异（这是本节的学习对象，不是脚手架的缺陷）：

#差异点我们的 tinyQwen3-0.6B处理
1QK-Norm无每头 RMSNorm（q_norm/k_norm，作用于 dh）进阶实现补齐——对齐失败的首要原因
2head_dim 与 d 的关系dh=d/hqdh=128 独立配置，hqdh≠d投影矩阵形状改为 d→h⋅dh
3lm_head 与 embedding独立权重tie_word_embeddings=truelm_head 复用 embedding 权重
4rope_theta100001,000,000（长上下文外推）配置化
5精度路径fp32bf16 权重 → CPU 以 fp32 装载记录容差实测值
6RoPE 配对方式interleave（相邻配对）half-split（前半/后半配对，rotate_half）cos/sin 表扩到 dh 维，前/后半同频

差异 6 是对齐实测中撞见的：half-split 配对下 rotate_half 的输出仍是 dh 维，cos/sin 表也必须扩到 dh 维（前半与后半用同一组频率）——形状对了数值才对得上。差异清单的工作流：每补齐一项复跑一次对照、记录容差变化，全部通过后冻结清单。本轮实测（CPU fp32，固定 6 token 输入）：

text
max|Δ| = 4.435e-05（相对 1.469e-06）≤ 1e-4，argmax 序列逐位置一致 → PASS
1

对齐是正确性结论：它证明我们对前向的理解与真实实现一致；速度没有任何结论（5.3）。

练习与答案 ​

练习 1：手算 softmax，输入分数 {1.414, 0.707, 0}（2.2 位置 2 的缩放后分数），给出权重并验算和为 1。答案：e 幂 ≈{4.113, 2.028, 1.000}，和 ≈7.141，权重 ≈{0.576, 0.284, 0.140}（和 ≈1.000）。若先减去最大值 1.414 再算，结果完全相同——数值稳定 softmax 的不变性。

练习 2：tiny 配置下，B=2,T=50 的一次 prefill：写出 q/k/v/o 四个投影的输出形状与 KV 缓存新增字节数。答案：q [2,4,50,16]、k/v [2,2,50,16]、o 输出 [2,50,64]；KV 新增 =2(K,V)×2层×2hkv×16dh×50×2B×4B=51200 B = 50 KB（公式与第 3 章 3.1 的账一致）。

练习 3：为什么 KV 缓存里存"已旋转的 K"是合法的，而不必缓存"未旋转的 K + 位置"？答案：RoPE 性质 1——旋转只依赖该 token 的绝对位置，一次旋转的结果永久有效；后续任何 query 在位置 t 与它做点积，用的都是这个定值。存未旋转版本意味着每次注意力都要重放旋转（多一遍计算），不改变语义只增加成本。

练习 4：SwiGLU 参数量是 3ddff，普通两层 FFN 是 2ddff。若要两者参数量相等，SwiGLU 的 dff 应取多少（普通 FFN 取 dff=4d）？答案：3ddff′=2d⋅4d⇒dff′=83d≈2.67d。这正是真实模型 FFN 中间维的常见压缩（tiny 的 176 ≈ 2.75×64 同此逻辑）。

练习 5：进阶对齐实验中，若注释掉 q_norm/k_norm（差异 1 不补齐），你预期单步 max|Δ| 会怎样变化？如何验证？答案：从 10−5 量级显著增大（QK-Norm 直接改变每头 Q/K 的尺度，进而改变全部注意力权重与下游残差）。验证：注释后复跑 run_qwen3_alignment.py，记录新的 max|Δ| 与 argmax 是否仍一致——"每补齐一项复跑一次对照"就是差异清单的工作流，误差量级的变化本身就是该项差异重要性的度量。

练习 6：greedy_decode 里 logits[0, -1] 取的是哪一行的预测？如果误写成 logits[0, -2]，生成的输出会变成什么样？答案：[0,-1] 是"看过全部已知 token 后对下一位置的预测"；写成 -2 会用倒数第二个位置的预测选 token，即每次选择的是"上上一步就该说的词"，输出整体错位且通常立刻退化为重复（可动手改一行观察——恢复后跑 run_alignment.py 实验二应回到 PASS）。

小结：算了什么、慢在哪里、怎样验证 ​

  • 一条请求在前向里走过了 embedding → 逐层（norm → 注意力 → norm → FFN）→ lm_head，每步的形状都能手推；形状错误在构造期或 reshape 处暴露，定位从报错 shape 反推投影层；
  • 注意力手算例子覆盖了缩放、因果 mask、数值稳定 softmax 与 GQA；RoPE/SwiGLU/RMSNorm 各自的"输入、输出、成立条件"有代码与测试对应；
  • 贪心解码循环 = 前向 + argmax + 停止判断；增量与全量前向数值一致，为下一章的测量和第 4 章的缓存铺路；
  • 对齐真实权重的判据是"每补齐一项差异复跑对照、记录容差"，冻结的差异清单（6 项）成为后续章节的引用锚点。

下一章给这套前向计时、算账：一次前向要读写多少字节、FLOPs 是多少、哪一段是瓶颈——以及一个最容易踩的坑：不同步设备就计时，会看到假加速。
